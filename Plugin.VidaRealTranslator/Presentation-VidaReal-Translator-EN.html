VidaReal Translator

Automatic AI translation of the Rock RMS interface with permanent caching — built in-house, without modifying Rock’s core.

Executive brief · August 2026 · Plugin version 1.2.0

1Executive summary

Rock RMS — the platform that manages the people, groups, events and check-in of the church — ships in English only. That slows adoption among staff and volunteers. VidaReal Translator translates the entire interface into Spanish (or any language) automatically and transparently for the user.

The core idea: every interface string is translated by AI once and is then stored in our own database. From the second user onward, the translation comes out of the cache — instant and free. AI spend trends to zero as usage grows.

2What the user sees

  • The whole interface in Spanish: menus, buttons, forms, validation messages and help text — on the intranet, the public site and check-in.
  • Optional language switcher (Weglot-style): a discreet tab to switch between Spanish, English or other languages. The preference is remembered per device.
  • Zero friction: nothing to install, no change to their workflow. If anything fails, the page simply shows in English — it never breaks.

4How it works at the DOM level

The translator touches no server-side HTML or templates: it operates on the already-rendered DOM in the browser, as a visual layer. Every string goes through a 5-step pipeline:

1 · Collect
walks text nodes, visible attributes and button labels
2 · Filter
exclusions + heuristics: anything that looks like data never leaves the browser
3 · Normalize
collapsed whitespace → identical canonical key on client and server
4 · Resolve
local cache → DB → AI, in batches of up to 200 strings per request
5 · Apply
text and attributes only; never innerHTML → HTML injection is impossible

Fig. 2 — Pipeline in the browser. Steps 1–3 and 5 are local; only step 4 can touch the network.

Anatomy of a page: what it touches and what it does not

<label>First Name</label>✓ translatesinterface text
<input value="Juan Pérez">× untouchedform value: whatever is typed or saved is never touched
<input type="submit" value="Save">✓ translateshere value is the visible button label, not data
<div title="Print this page">✓ translatesvisible attributes: title, placeholder, aria-label, alt
<table class="grid-table">
<th>Email Address</th>✓ translatescolumn header = interface
<td>juan@vidareal.tv</td>× untoucheddata cell: excluded wholesale, never even sent
<span>{{ Person.NickName }}</span>× untouchedLava token / variable
<textarea>...</textarea>, <pre>, <code>, contenteditable× untouchededitable or technical content, excluded wholesale

In addition, any element can be excluded individually with the class notranslate or the attribute data-no-translate, and there are selector lists configurable from the admin without recompiling.

  • Idempotent and efficient: nodes that have already been translated are marked and never reprocessed; strings already known come out of the cache without touching the network.
  • Safe application: text is replaced node by node, preserving edge whitespace; innerHTML is never used, so the AI cannot introduce HTML or scripts.
  • Fail-safe: every step runs inside error guards; an invalid selector or an odd response is discarded without affecting the page.

Coverage of dynamic content

Rock builds its pages from blocks that arrive at different moments. The translator covers all four paths:

ScenarioMechanism
Initial load and late renderStaggered passes (0 / 600 / 1500 ms) over the whole page.
Content injected by AJAX / modern blocks (Obsidian)MutationObserver: watches the DOM and processes only the new subtrees (it does not re-sweep the page), grouping changes with a small debounce.
Partial postbacks (classic WebForms screens)Hook into the ASP.NET AJAX lifecycle (PageRequestManager): re-scans when each postback finishes.
Navigation without reload (SPA)Hook into the History API (pushState / popstate): re-scans on route change.

6Protection of member data

A non-negotiable design rule: «interface yes, data no». The filter runs in the browser before anything is sent: whatever looks like data never leaves the device.

✓ Translated× Never sent, never touched
Buttons, menus, titles, form labels, validation messages, help textPeople’s names, emails, phone numbers, amounts, dates, the contents of data tables, fields that are typed in or saved, editable content
  • The values that travel to the server are excluded by design: a translation cannot corrupt what gets stored in the database.
  • The AI response is sanitized (any code or markup is stripped) before being stored or displayed.
  • Aligned with the Responsible AI Use Policy: only software vocabulary ever reaches the AI, never member information.

7Administration (inside Rock itself)

Everything is managed from a single admin page: Admin Tools → Installed Plugins → VidaReal Translator. No need to touch servers or databases.

FunctionDescription
On / offA single toggle activates the translator on every Rock site at once; switching it off removes it just as cleanly. Fully reversible.
Editorial controlA listing lets you search any translation and correct it by hand (the correction is locked in: the AI will not touch it again), exclude strings that must never be translated, or delete them to regenerate.
Cache purgeRegenerates every translation (e.g. after improving the AI style instructions). Administrators only.
ConfigurationTarget language, Azure credentials (stored encrypted), the languages in the switcher and fine-grained scope settings — all through the standard Rock form.

8Quality and robustness

  • Graceful degradation: in the face of any failure (AI down, network, configuration), the page is shown in English. The translator never breaks a screen or a save.
  • Professional translation: the AI is instructed to use standard software terminology in Spanish, a consistent tone and a similar length (so the layout does not break).
  • Verified integrity: automated tests cover the data safeguards and the exact parity between the browser code and the server code.
  • Built to grow: it supports several languages in parallel (each with its own cache) and the architecture allows switching AI provider without rewriting the system.

In summary

A one-time development investment that makes Rock accessible in Spanish for the whole team, with a marginal and decreasing operating cost (trending to zero), full editorial control and zero risk to the data of the congregation.

The same architecture works for any target language: each one keeps its own permanent cache, and adding one does not change a single line of Rock.
